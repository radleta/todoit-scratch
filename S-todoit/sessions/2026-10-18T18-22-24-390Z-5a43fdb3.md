## Decisions made

- The code repo's base is `develop`; scratch's base is `main`; the code repo's `main` is only moved by a deliberate merge from `develop`, which is also how the site publishes.
- Lanes run as worktrees (`lane open <slug>`, open at launch), so the build, including `/brainstorming`, runs inside the lane; this workstream stays the project-management stream in the main checkout.
- todoit v1 is a static site of plain HTML and JavaScript modules (no build step) on GitHub Pages from `main`, with todos in IndexedDB behind a versioned storage module, unit tests for DOM-free logic and Playwright tests for the main flows. Full decision lines with reasons are in `scratch/issues/todoit-v1.md` `## Decisions`.
- "Fun" means the five principles in `scratch/repo-setup/fun.md` (impact, reward, challenge, fantasy, people differ); the user said "we want the app to be fun following these principles", so the wiki page applies them to the whole app, not only v1.
- The interaction is `jar-ring` and the look is `washday`; grouping todos by date with day jars is a later idea kept out of the epic so v1 can push toward a release.
- The app is one build (no forcing condition splits it); publishing is a second build behind a merge gate.

## What to avoid

- Don't run `lane remove` on Windows until the upstream bug is fixed; from the main checkout use `git -C scratch worktree remove ../../todoit-{slug}/scratch` then `git worktree remove ../todoit-{slug}` (`-C scratch` resolves relative paths from inside `scratch/`, so it needs `../../`).
- Commit scratch before `lane open`: the lane's scratch worktree is cut from the last commit on scratch `main`, so uncommitted issues and prototypes are missing inside the lane.
- `lane open {slug}` needs an existing `scratch/issues/{slug}.md`; without one `/begin-lane` cannot open the lane and only the detached worktrees are left.
- In Git Bash, `claude mcp add ... -- cmd /c ...` turns `/c` into `C:/`; set `MSYS_NO_PATHCONV=1`.
- `write_issue` titles over 80 characters are rejected; a JSON heredoc with literal backslash paths can fail to parse, so describe Windows paths in words.
